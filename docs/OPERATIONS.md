# Operating the claims pipeline

[Project overview](../README.md) · [Validation and deployment scope](VALIDATION.md)

## Inputs and parameters

The generator writes synthetic `claims.csv` and `providers.csv`. Load these into the Databricks Volume and use `00_setup_raw` to create the Parquet inputs expected by the monthly DAG:

```text
/Volumes/workspace/max1102_pipeline/raw/claims.parquet
/Volumes/workspace/max1102_pipeline/raw/providers.parquet
```

| Parameter | Meaning |
|---|---|
| `month` | Report month in `YYYY-MM` format |
| `raw_dir` | Volume directory containing the Parquet inputs |
| `batch_id` | Run identifier generated by Airflow |

The published table is `workspace.max1102_pipeline.report_monthly`, with `specialty`, `claim_count`, `total_amount` and `report_month`. Only paid claims contribute. The load replaces the requested month and retains all other months.

## Execution prerequisites

The repository copy of `00_common.py` lacks helpers used by the original notebook tasks. Restore and review the intended workspace exports before running or deploying that path. The dbt models are a separately validated transformation path and require Databricks activation and reconciliation before replacing it.

The original notebook jobs are `max1102_01_extract`, `max1102_02_validate`, `max1102_03_transform` and `max1102_04_load`. The Airflow connection is `databricks_default`; configure the CLI profile through `databricks configure`. Keep `.env` and credentials outside Git.

## Start Airflow

After configuring `.env`, the connection and job IDs:

```bash
docker build -t max1102-airflow:3.2.0 airflow
docker compose up airflow-init
docker compose up -d
```

Open port 8080 through the Codespaces Ports panel. Trigger the monthly DAG manually with the required parameters. Its stages are preparation, extraction, validation, transformation, load and completion logging. It permits one active run.

## Validate the DAG definition

```bash
docker run --rm \
  --entrypoint python \
  -e AIRFLOW__CORE__LOAD_EXAMPLES=False \
  -v "$PWD/airflow/dags:/opt/airflow/dags:ro" \
  -v "$PWD/tests:/opt/project/tests:ro" \
  max1102-airflow:3.2.0 \
  /opt/project/tests/check_dag.py
```

This checks the DAG definition in the Airflow image; it does not execute Databricks transformations. CI runs the same definition check.

## API and retrieval

The API exposes `/claims/llm-summary` and `/claims/rag-summary`, protected by the configured API key. `RAG_ENABLED=true` also routes the original summary endpoint through retrieval. RAG requires an indexed reference corpus, PostgreSQL/pgvector, provider credentials and model configuration.

`/health` checks application process health. It does not call Gemini or establish that document indexing is current. Verify authenticated RAG responses separately, including sources, supported numeric values and requests with insufficient context.

## Stop and recover

Wait for the active DAG to finish before running its notebooks manually or stopping the environment.

```bash
docker compose down
```

Stop the Codespace from GitHub when finished. Commit and push intended source changes before deleting it; keep secrets excluded. For a failed run, inspect the failing task and its quality report or provider error before retrying, and verify that the selected reporting month is consistent after recovery.
